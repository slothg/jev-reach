# 预览会话排队设计

日期：2026-10-13。状态：已实施并部署，限定验证及现有预览只读交接通过。
原计划编号：JEV-06；承接 [共享服务优化计划](../shared-service/jev-reach-optimization-plan.md) 的 JEV-01 单次操作队列。
执行计划：[预览会话排队计划](./preview-session-queue-plans.md)。

## 目标与现状

多个 Codex 聊天可以同时分析代码，但通过当前共享调试后端进行预览测试时，全局只允许一个聊天占用浏览器。占用覆盖一整轮测试，包括相邻工具调用之间的等待、截图取证和清理。其他聊天按申请顺序排队。

当前源码事实：

- `src/scheduler.ts` 的 `OperationQueue.run()` 串行执行单次调用，完成后即允许下一个调用进入；`serializeTools()` 没有整轮测试的会话所有者。因此 A 的调用结束、B 操作页面、A 再继续的顺序仍被允许。
- `src/http.ts` 已维护独立 MCP session、退出和过期清理，可用于识别调用来源与撤销排队资格。
- `release_page` 释放页面采集资源，不代表结束整轮测试，也没有阻止其他会话调用浏览器工具。
- Cocos QA 的 `WebRunner` 为每个客户端创建独立 Chrome MCP 连接；当前 QA 已有全局单会话文件锁，但不能阻止普通 Chrome 工具修改页面。QA 用例也通过 Runtime WebSocket 读取状态，不能只在 Chrome 点击入口加锁。本次沿用现有 QA 锁，不增加第二把 QA 文件锁。

上述事实足以确定当前机制没有会话级独占；本轮没有重现或归因某一次实际测试失败。

## 唯一占用权

复用共享后端和现有操作队列，在同一进程内增加一份全局测试占用状态及 FIFO 等候队列。多个 MCP 连接仍可初始化、发现工具、保持协议连接；同时只有一个逻辑聊天组可以执行浏览器操作。不同页面也共用一个名额，符合“同时只能让一个会话使用”的要求。

一个逻辑聊天组可以包含该聊天的普通 Chrome MCP 连接和 QA 内部 Chrome 连接。组间互斥，组内单次浏览器调用仍由现有 `OperationQueue` 串行执行。关联依据为后端签发、绑定本次占用的随机凭证，不按 pageId、页面 URL、客户端显示名称或猜测的聊天 ID 合并所有者。

占用检查覆盖共享后端的浏览器工具，包括页面发现、选择、刷新、脚本、截图、Console/Network、输入、QA helper 和 `reach`。协议初始化、工具目录、MCP ping、排队状态和取消/释放接口不占用浏览器。界面中的人工操作、其他外部 CDP 客户端和绕过此共享服务的独立服务不在本后端的强制控制范围内。

## 申请、等待与交接

增加窄接口 `debug_session_acquire`、`debug_session_release`、`debug_session_status`，通过现有 `chrome-devtools` MCP 暴露。接口描述明确申请整轮测试、取得资格后执行、finally 释放的顺序。

- 申请成功返回本次占用标识和本地关联凭证。重复申请不重复入队，也不改变已排定顺序。
- 等待单次最多 30 秒，返回清晰的等待状态、队列位置和当前占用标识；等待超时不代表操作成功。保留有时限的申请票据，后续查询/继续等待沿用原位置，不建立后台工具重放任务。
- 新流程在首次浏览器操作前显式申请，整轮取证和清理结束后释放。旧客户端没有使用新接口时，首次浏览器调用自动进入相同准入流程；未获资格时不执行该调用。被拒绝/取消的输入不会在后台延迟执行。
- 占用等待位于单次操作队列之外；状态查询、取消、会话退出和必要的清理不能被等候者堵住。实际执行前再次检查所有者和占用代次，防止已过期的旧调用迟到执行。
- 交接先停止旧代次的新操作，完成其活动操作与自身预览资源清理，再允许下一个所有者进入。不得仅更换 owner 字段而让旧操作继续访问页面。

## 生命周期

正常结束主动释放；等待者取消、客户端退出或会话被删除时移出队列。复用 HTTP session 的退出与清理入口，不新增常驻进程、系统服务或另一套跨进程锁。

默认闲置 10 分钟回收占用。只有实际浏览器活动和受该占用保护的 QA 活动可以续期；MCP 连接存活、普通 ping 和后台心跳不续期。尚在执行的浏览器操作或 QA 用例不因闲置计时被转交。

闲置回收需先撤销旧代次和清理其预览资源。旧所有者恢复测试时必须重新取得资格。活动 CDP 请求或清理无法结束时，保持阻塞并报告原因，不以放行下一会话制造新的并发；也不自动关闭用户 Chrome 或强制结束其他聊天。

同一占用的 QA 子连接退出只清理自身资源；整轮释放要等组内活动完成。组的持有连接异常退出时撤销该组资格，并清理其相关 QA 接入后交接。

## Cocos QA 接入

在现有 QA 流程接入同一占用权，保留物理目标锁、原有鉴权、适配器与输入回执要求。

- QA 单独运行时，页面发现/接入前申请并持有占用，detach/close 后释放。
- 一个聊天混用普通 Chrome 工具与 QA 时，通过可选关联凭证让 QA 内部连接加入已经取得的占用。新增参数不替换 `pageBinding`，不把整个页面列表对象当作绑定，不重新猜测物理目标。
- Web prepare、用例执行、手动 Web Runtime 查询/动作和清理均检查占用；Runtime WebSocket 操作不能成为绕过准入的入口。活动用例的续期与回收必须覆盖整个用例执行边界。
- 无效、过期或属于其他占用的关联凭证不得接管现有组；在任何页面输入前返回明确失败。
- 未获资格时返回等待状态，不另开预览页、不回退为绕过锁的 Console 测试。

## 验收标准

1. A 连续执行多步测试时，B 的操作不会插入；不同页面也不能同时占用。A 清理释放后，B、C 按 FIFO 获准。
2. 同一聊天普通调试与 QA 子连接可共用占用，不互相死锁；其他聊天的普通工具及 Web QA 路径均被挡住。
3. 等待取消、超时、连接退出、闲置回收和凭证失效均无输入重放；释放后旧代次不能继续操作。
4. 组内嵌套工具仍可运行，等待不阻塞状态查询和清理；活动操作/用例不因闲置回收失去保护。
5. MCP 初始化和心跳不误占用或延长测试资格；原有页面/roots 隔离、QA 目标鉴权和失败回执语义保持有效。
6. 安装包与源码构建一致，当前运行服务报告新版本；在一个明确选择的现有预览页上完成两个客户端的只读排队交接。真实点击争用先在隔离的本地浏览器夹具验证。
